
## Фактическое состояние backend после аудита

Добавлены серверные маршруты `/api/session`, `/api/pair`, `/api/pair/invite`, `/api/pair/join`, `/api/wishes` и `/api/household`. Они используют Telegram `initData`, проверяют подпись через `TELEGRAM_BOT_TOKEN`, ограничивают данные текущей парой и используют версии записей для защиты от тихого перезаписывания изменений партнёра.

Добавлена миграция `drizzle/0001_pale_butterfly.sql` с таблицами `couples`, `synced_wishes` и `synced_household_tasks`. Миграция успешно сгенерирована и применена командой `pnpm db:push`.

Для реального включения онлайн-синхронизации всё ещё необходимо задать секрет `TELEGRAM_BOT_TOKEN` в защищённом окружении сервера. Без него API намеренно отвечает `telegram_auth_not_configured`; это означает, что клиент работает в локальном режиме, а не что синхронизация готова.

## Проверка двумя участниками

Оба участника должны открыть приложение внутри Telegram. Первый создаёт пару и передаёт код приглашения из раздела «Пара и синхронизация». Второй вводит код. После подключения нужно проверить добавление, редактирование, выполнение и удаление желания и бытовой задачи с разных аккаунтов. При одновременном редактировании должна появиться проверка версии, а не бесшумная потеря одной из версий.
