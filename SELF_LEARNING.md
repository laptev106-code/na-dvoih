## 🚫 РЕЕСТР ЗАПРЕЩЕННЫХ ОШИБОК (NEVER-REPEAT MATRIX)

### Инцидент №1: Ложный рапорт о деплое / Необновление продакшена
- **Симптом:** Пользователю сообщается, что изменения «уже на сервере / в проде», но пользователь открывает приложение и видит старую версию.
- **Первопричина:** 
  1. Команда `git push` обновляет только ветку на GitHub, но Render Web Service может не иметь включенного Auto-Deploy, требовать ручного триггера (Dashboard Manual Deploy) или собираться с задержкой в несколько минут.
  2. Отсутствие прямого контрольного `curl` с проверкой конкретных строк нового коммита на живом HTTPS-домене.
  3. Кэширование `index.html` в WebView Telegram без заголовков `Cache-Control: no-cache, no-store, must-revalidate`.
- **Инвариантное правило (Closed-Loop Prod Verification):**
  1. Запушить код в GitHub `main`.
  2. Инициировать деплой на хостинге (Render Dashboard -> Manual Deploy / Deploy latest commit).
  3. Дождаться сборки и статуса `Live`.
  4. **ОБЯЗАТЕЛЬНО** выполнить прямой сетевой запрос:
     `curl -s "https://na-dvoih.onrender.com/na-dvoih"` и подтвердить наличие уникальных маркеров из нового коммита.
  5. Только после получения физического `True` рапортовать пользователю!

### Инцидент №2: Просроченные даты без явной цветовой дифференциации в Календаре
- **Симптом:** В Календаре просроченные события выглядели так же, как обычные будущие, пользователю приходилось вчитываться в текст.
- **Инвариантное правило:**
  - Во всех экранах (Календарь, идеи, история) просроченные даты обязаны подсвечиваться теплым предупреждающим коралловым цветом (`var(--coral, #dc806a)` / `#ef4444` в тёмной теме), с индикатором `⏳ Просрочено`, выделенным бейджем и яркой точкой на сетке месяца.

### Инцидент №3: Нарушение автономности и лишние вопросы
- **Инвариантное правило:**
  - Пользователь выступает как Product Owner, не программист. Агент принимает все технические решения самостоятельно, не задает технических вопросов и проверяет все правки в терминале до вывода ответа.
